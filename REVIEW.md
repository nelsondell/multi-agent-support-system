# Evaluator guide

One row per V4 criterion: what shows it, the command that reproduces it with no key and no
network, and what it does not cover.

- **Every check at once:** `make verify` runs the suite, the guardrail eval and the eval replay;
  `make verify REPORT=1` records the result ([`reports/verify.md`](reports/verify.md)).
- **Decisions:** [`docs/adr/`](docs/adr/).
- **Rollout:** [`docs/pilot.md`](docs/pilot.md).

| Criterion (V4) | Evidence | Reproduce offline | Known limit |
| --- | --- | --- | --- |
| **Business & Challenge Fit** (9.5) | The ten scenarios, a follow-up, a compound request, the human loop and the confirmed write run against a clean copy, on one node and over two replicas ([`docs/demo.md`](docs/demo.md)). 100 sampled requests reach pass-all **94/100** ([`evals/eval_report.md`](evals/eval_report.md)). The corpus gained the FAQ category pages and three terminal manuals for the answers the error analysis found partial (T-53). A pilot by intent with numeric gates and a sourced cost table: [`docs/pilot.md`](docs/pilot.md). | `make eval-offline` | Account data is a mock backend. Open failures: C08, S02, S07, E08, X08, R06 ([`failure_modes.md`](evals/failure_modes.md)). The pilot's volumes and human costs are assumptions. |
| **Agentic Reasoning & Orchestration** (9.5) | The router plans one or two steps; a specialist's structured `need` lets the supervisor add a read step, drop one that did not answer, and stop on budgets ([ADR 0001](docs/adr/0001-bounded-replanning.md)). See [`app/graph/supervisor.py`](app/graph/supervisor.py) and the 7 tests in [`tests/test_replanning.py`](tests/test_replanning.py). On 20 requests that need a finding, replanning completes **32/60** against 19/60 without it, over three runs ([`evals/planning_report.md`](evals/planning_report.md)). | `uv run pytest -q tests/test_replanning.py tests/test_plans.py` | Bounded by design: at most 3 added steps a turn, no open loop ([ADR 0008](docs/adr/0008-considered-not-doing.md)). The planning eval needs a model key, and the simple requests' p95 moved inconsistently across its runs ([ADR 0001](docs/adr/0001-bounded-replanning.md)). The 28 misses mostly come from two causes ([`evals/planning_report.md`](evals/planning_report.md)): knowledge answers from the site without asking for the account fact that decides it, and support or the router escalates a request that a finding would have answered. |
| **Context, Knowledge & RAG** (9.7) | Hybrid BM25 + dense with RRF ([ADR 0004](docs/adr/0004-hybrid-retrieval.md)). The embedder separates in- from out-of-domain on 97 questions (AUC 1.000, gap 0.067). On 82 questions with gold chunks drafted by a reasoning model (every row reviewed by the owner, 0 edits), recall@5 is **0.939** and MRR **0.851**. Three rerankers were measured; Cohere met the rule but stays opt-in ([ADR 0002](docs/adr/0002-reranker-off-by-default.md)). | `uv run pytest -q tests/test_retrieve.py tests/test_knowledge.py tests/test_ingest.py` | The benchmarks need the embedder's key. A 600-token chunk can cut a table. One reviewer for the gold. |
| **Tool & Action Engineering** (9.5) | The merchant id never appears in a model schema: tools get it from graph state ([`tests/test_tools.py`](tests/test_tools.py)). One write, a technical ticket, runs only on the merchant's confirmation, once, audited ([ADR 0005](docs/adr/0005-write-behind-confirmation.md), [`tests/test_actions.py`](tests/test_actions.py)). Every tool's schema, effects and failures are in [`docs/tools.md`](docs/tools.md). | `uv run pytest -q tests/test_tools.py tests/test_actions.py` | The backend is a mock with one offline terminal. |
| **Security & Identity** (9.3) | RS256 JWT, with the merchant id taken only from `sub`. Operator and supervisor roles, an append-only audit log, LGPD erasure and retention, and a per-subject rate limit ([ADR 0007](docs/adr/0007-jwt-identity.md), [`tests/test_security.py`](tests/test_security.py)). OWASP ASI01–ASI10 mapped to controls and tests in [`docs/security.md`](docs/security.md). The red team is **40/40** safe. | `uv run pytest -q tests/test_security.py tests/test_adversarial.py` and `make eval-offline` | The dev identity provider is a local key pair. The rate limit counts per replica. |
| **Memory, State & Resilience** (9.4) | Checkpoints on SQLite, or Postgres for replicas ([ADR 0006](docs/adr/0006-postgres-for-replicas.md)), plus a rolling summary ([`tests/test_memory.py`](tests/test_memory.py)). [`tests/test_replicas.py`](tests/test_replicas.py) runs in CI over Postgres: a cross-replica handoff, a replica killed mid-turn, and serialized turns. LangGraph retry, timeout and error handler on every node ([`tests/test_resilience.py`](tests/test_resilience.py), deterministic). | `uv run pytest -q tests/test_memory.py tests/test_resilience.py tests/test_locks.py` | The replica tests need `TEST_DATABASE_URL`. The knowledge index is per node, rebuilt from the snapshot. |
| **Human Oversight & Risk Management** (9.7) | Handoffs use `interrupt()`. The operator can approve, reply or cancel. A rephrasing that adds a number or flips a status falls back to the operator's text. Cases expire by TTL, the plan resumes after the reply, and the merchant confirms the one write ([`tests/test_human_review.py`](tests/test_human_review.py), 21 tests; [`docs/human-in-the-loop.md`](docs/human-in-the-loop.md)). | `uv run pytest -q tests/test_human_review.py tests/test_handoffs.py` | The operator's interface is the API. |
| **Evaluation & Quality Engineering** (9.7) | **362 tests.** Error analysis: 100 real traces, labels drafted by a reasoning model; every row reviewed by the owner, 0 edits; five failure modes, one binary check each ([`evals/failure_modes.md`](evals/failure_modes.md)). The replay gates every PR, with floors set from the accepted recording ([`evals/thresholds.toml`](evals/thresholds.toml)). The 40-case red team is tagged with OWASP ids. | `make verify` | The judge is not validated: there are 5 labelled failures of its mode, so it runs as a regression check. The prompt fixes were made on the same 100 traces. |
| **Observability, Reliability & Cost** (9.2) | OpenTelemetry GenAI spans, with no content. Metrics: cost per resolution, resolution without a person by intent, escalations by reason, and p50/p95 per node. A Grafana dashboard and four alerts, each with a runbook line ([`docs/operations.md`](docs/operations.md), [`tests/test_otel.py`](tests/test_otel.py)). Measured on 100 traces: **US$ 0.00048** of model spend per resolved turn ([`docs/pilot.md`](docs/pilot.md)). | `uv run pytest -q tests/test_otel.py tests/test_telemetry.py tests/test_resilience.py` | The GenAI conventions are still in Development. The prompt cache's effect is not measured. |
| **Production Engineering** (8.6) | `make verify` from a clean copy: no key, and no network after the sync, with a committed tokenizer. CI runs it on ubuntu with the network cut and on macOS. Base images are pinned by digest, with an SBOM, trivy, gitleaks and Dependabot. `make scale` runs replicas over Postgres. | `make verify` | `make up`, `make scale` and `make observe` ran from a clean copy on macOS ([`docs/demo.md`](docs/demo.md)); on Linux, only `make verify` and the container job, in CI. |
| **Engineering Judgment** (9.8) | Each choice has a measurement or an ADR: the model (`evals/router_benchmark.md`), the embedder and threshold (`evals/retrieval_calibration.md`), the reranker (`evals/rerank_benchmark.md`), and ADRs 0001–0008, including what was considered and not done. | — | |
